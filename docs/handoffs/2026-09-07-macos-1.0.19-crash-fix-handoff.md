# macOS 1.0.19 Crash Fix Handoff

Date: 2026-09-07

## Root cause

The published 1.0.18 app was assembled by replacing managed DLLs in an older
publish bundle. `LeikwanBridge.Mac.dll` referenced
`LeikwanBridge.Core, Version=1.0.18.0`, while the copied Core assembly had
assembly version `1.0.0.0`. The bundle also retained a 1.0.15 dependency
manifest. On launch the CLR raised `FileNotFoundException` for
`LeikwanBridge.Core`; macOS then reported `Abort trap: 6`.

## Fix

- Build both RIDs from one clean `dotnet restore` + `dotnet publish`.
- Pass the release version to restore as well as publish.
- Require the four managed publish files and validate the `.deps.json` RID,
  app version, and project assembly entries before packaging.
- Run a managed bundle-load probe on the host architecture. Cross-architecture
  packaging requires a receipt bound to the four file SHA-256 values.
- Added regression coverage for missing, stale, invalid, and changed managed
  files.
