# Managed TYO UDP Transport Smoke Runbook

This smoke validates the current sh36 live host and the panel-driven managed TYO transport checks around it. It is not the architecture itself.

## Secret handling

- Do **not** store passwords in this repo.
- Export `SH36_PASS` (and any optional sidecar-hop command inputs) from your local credential files before running the script.
- If a sidecar service restart is needed, do it **through the slave hop**. Do not SSH to the sidecar directly from your workstation.

## Checks

1. `lgtcp-12022.service` is persistent, enabled, and active on sh36.
2. `leigod-tcp-forwards-reconcile.path` and `.timer` are enabled and active on sh36.
3. `lgfwd.service` is inactive on sh36.
4. sh36 is listening on TCP/12022 with the expected local forwarder.
5. Running `/opt/leigod/scripts/reconcile-tcp-forwards.py` when it prints `unchanged lgtcp-12022.service` must keep the `lgtcp-12022.service` `MainPID` unchanged. A reconcile loop that stops/restarts unchanged units will cut active sessions once per timer cycle.
6. The Tokyo sidecar managed iperf target must be generated by the sidecar agent as a bounded one-client loop, not a raw long-lived `iperf3 -s`:
   - expected unit shape: `timeout --kill-after=3s 12s /usr/bin/iperf3 -s -p 5201 --one-off --idle-timeout 5`
   - expected installed generator snippet: `/usr/local/bin/leikwan-sidecar-agent.py` contains `timeout --kill-after=3s 12s {iperf3_bin}`
7. Optional: a sidecar restart/audit command can be injected via the slave hop before the final `iperf3` check.
8. Durable UDP rollout validation must additionally verify the panel-published `sidecar_uplink` payload and the agent-created `lguot` + WireGuard services for clean installs.

## Live fixes captured during validation

- sh36 live patch: `/opt/leigod/scripts/reconcile-tcp-forwards.py` now stops only changed units before `daemon-reload`; unchanged `lgtcp-*` services stay running.
  - backup: `/root/leigod-forward-backups/reconcile-tcp-forwards.py.20260606-143610.bak`
- Tokyo sidecar live patch, reached through the sh36 slave hop: `/usr/local/bin/leikwan-sidecar-agent.py` and `/etc/systemd/system/leikwan-bond-sidecar-5-iperf3-5201.service` now use the bounded one-off loop above.
  - backups: `/root/leikwan-sidecar-backups/leikwan-sidecar-agent.py.*.bak` and `/root/leikwan-sidecar-backups/leikwan-bond-sidecar-5-iperf3-5201.service.*.bak`
- Root cause verified live:
  - stale/raw clients could occupy iperf3 while systemd still reported the service active;
  - the bounded loop recovered after a stale raw connection and `iperf3 -c 127.0.0.1 -p 12022 -t 3 --forceflush` then completed;
  - sh36 reconcile timer cycles left `lgtcp-12022.service` on the same PID and subsequent iperf still completed.

## Command

```bash
bash scripts/managed-tyo-udp-smoke.sh
```

To include the sidecar generator/unit invariant, pass a command that audits it through the sh36 slave hop; do not connect directly from the workstation to the sidecar.
