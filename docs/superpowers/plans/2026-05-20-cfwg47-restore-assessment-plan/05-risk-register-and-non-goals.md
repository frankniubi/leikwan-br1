# CFWG Forward 47 Risk Register and Non-Goals

Source handoff: [`leikwan-br1/docs/superpowers/handoffs/2026-05-20-cfwg47-known-good-restore-assessment.md`](../../handoffs/2026-05-20-cfwg47-known-good-restore-assessment.md)

This document is the fifth and final deliverable of the CFWG forward 47 assessment plan. It pairs the explicit non-goals carried forward from the handoff at `leikwan-br1/docs/superpowers/handoffs/2026-05-20-cfwg47-known-good-restore-assessment.md` with additional non-goals discovered during this planning pass, then enumerates eight risks (R-01 through R-08) with mitigations and owners. The handoff's "Do not do these things during assessment" list is carried forward verbatim below; treat that list as binding for every agent and operator working on this remediation, not just for the planning pass that produced these five docs. Companion documents in this directory are [`01-cfwg-contract-assessment.md`](./01-cfwg-contract-assessment.md), [`02-priority-mapping.md`](./02-priority-mapping.md), [`03-regression-fixture-plan.md`](./03-regression-fixture-plan.md), and [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md).

## Carried-forward non-goals (from handoff)

The four bullets below are quoted verbatim from the handoff's "Do not do these things during assessment" section. Markdown backticks around inline code spans are preserved exactly as the handoff renders them.

- Do not switch topology to direct client-to-sidecar. This environment must preserve `client -> slave -> sidecar` where applicable.
- Do not delete the known-good backup under `/root/leikwan-mptcp-leg-priority-sh36-20260519-005901`.
- Do not re-enable auto-update until the current panel artifact has been proven to render the same working CFWG contract.
- Do not treat service `active` alone as proof; the decisive proof is WireGuard receive traffic and successful reachability to `10.204.53.42`.

The first bullet rules out a topology shortcut that has been proposed in prior incidents. The second pins the rollback baseline. The third is the precondition for everything in [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md). The fourth is the operational discipline that keeps "the service is running" from being mistaken for "the path is working".

## Additional non-goals discovered during this assessment

These are non-goals that surfaced while writing the four prior documents. They are additive to the handoff list, not substitutes for it.

- Do not modify production code under `leikwan-br1/` in the planning pass. The user's hard rule for this task is "Do not modify production code in this pass. Plan only." Every concrete change proposed in `02-priority-mapping.md`, `03-regression-fixture-plan.md`, and `04-rollout-unpin-runbook.md` is described as future work for a coder agent, not as a patch to apply now. The `git -C leikwan-br1 status --porcelain` check in the verification block is the safety net that enforces this.
- Do not commit raw live-captured fixtures with real CF dial IPs, real SNI hosts, real WG public keys, or real agent tokens. The FEAT-002 scrubbing rules in [`03-regression-fixture-plan.md`](./03-regression-fixture-plan.md) "Scrubbing rules" subsection must be applied before any byte under `leikwan-br1/client-agent/tests/fixtures/cfwg-forward-47/` or `leikwan-br1/sidecar-agent/tests/fixtures/cfwg-forward-47/` is committed. The substitution table covers `162.159.39.5`, `nrt1.nbwly.com`, the live sidecar `[Peer] PublicKey`, and the live `path_prefix` hex; `agent_token`, `agent_update_request_token`, and any WireGuard `[Interface] PrivateKey` value must additionally be replaced with placeholders before commit.
- Do not regenerate `leikwan-br1/artifacts/versions.json` hashes blindly without confirming which artifact lineage the panel actually serves. Three lineages are currently in flight per [`01-cfwg-contract-assessment.md`](./01-cfwg-contract-assessment.md): for `client_agent.py` the manifest declares `75354f40...`, the in-tree file hashes to `ebae5089...`, and the live restored on `sh36` hashes to `3abb7ecd...`; for `install_forward_runtime.py` the manifest declares `f88c4c2f...`, the in-tree file hashes to `9341ed77...`, and the live restored hashes to `2e4c0c88...`. A blind regeneration of the manifest from the in-tree files would write `ebae5089...` and `9341ed77...` into the manifest and ratify whichever lineage happens to be checked out, masking the underlying contract drift. The next coder must first decide which lineage is the source of truth (the manifest, the in-tree files, or the live restored bytes) and document that decision before regenerating.
- Do not ship a fix to the path-prefix `.cfwg` suffix without first confirming whether `forwards.path_prefix` carries a leading slash in the production DB. `leikwan-br1/master/src/Support/ProvisioningService.php` does pure string concat with `.cfwg`, so a leading slash on `forwards.path_prefix` compounds into `/<hex>.cfwg` which the live working runtime does not use (the live runtime uses the no-leading-slash form `07289d1f5ed25399.cfwg` per the handoff Pre-fix failure evidence section). The fix is either to normalize on the panel side or to assert on the client side; choose one, write a regression test, and only then ship. See risk R-07 below.

## Enforcement of the non-goals

Each non-goal above is enforced by a concrete check that lives somewhere in the five-doc plan. The list below maps each non-goal to its enforcement point so the next agent can see at a glance which doc fails the rollout if a non-goal is violated.

- "Do not switch topology to direct client-to-sidecar" is enforced by [`01-cfwg-contract-assessment.md`](./01-cfwg-contract-assessment.md) section A (the `self_leg_cf_transport='cf_wg'` semantic) and section C (the sidecar peer pubkey selection); both presume the `client -> slave -> sidecar` topology. A topology switch would produce diff failures across multiple sections of the FEAT-002 harness.
- "Do not delete the known-good backup under `/root/leikwan-mptcp-leg-priority-sh36-20260519-005901`" is enforced by [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md) Section 6, which restores from that backup path on rollback.
- "Do not re-enable auto-update until the current panel artifact has been proven to render the same working CFWG contract" is enforced by [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md) Section 2, the pre-flight harness gate.
- "Do not treat service `active` alone as proof" is enforced by [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md) Sections 1 and 5, which require `wg show` non-zero `received` plus `ping` 0% loss as the success criterion.
- "Do not modify production code under `leikwan-br1/`" is enforced by the FEAT-003 verification block running `git -C leikwan-br1 status --porcelain` and asserting empty output.
- "Do not commit raw live-captured fixtures" is enforced by [`03-regression-fixture-plan.md`](./03-regression-fixture-plan.md) "Scrubbing rules" subsection.
- "Do not regenerate `artifacts/versions.json` blindly" is enforced by R-06 below and by the open question about which panel-side script regenerates the manifest.
- "Do not ship a path-prefix fix without confirming the leading-slash question" is enforced by R-07 below and by the open question about the production DB shape of `forwards.path_prefix`.

## Risk register

Eight risks are enumerated below. Each row carries a Risk ID (R-01 through R-08), a description, a likelihood rating, an impact rating, a mitigation, and an owner. Likelihood and impact use the labels low, medium, and high without further calibration; this is a planning-pass register, not a quantitative model. Owners are roles, not individuals.

| Risk ID | Description | Likelihood | Impact | Mitigation | Owner |
| --- | --- | --- | --- | --- | --- |
| R-01 | Panel push regresses CFWG contract during unpin: clearing `disable_auto_update` lets the panel updater overwrite the working local runtime with a build that does not render the same wstunnel client / wg conf / sidecar route trio, regressing forward 47 immediately after the toggle. | high (without harness) | high | The FEAT-002 diff harness is a hard pre-flight gate in [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md) Section 2; the four diff tests plus the manifest consistency check must all be green against fresh live-captured fixtures before either Section 3 or Section 4 is attempted. | rollout operator |
| R-02 | Fixture-vs-live drift over time as the panel evolves: a captured `panel-payload.json` from one panel build will not match a later panel build, even if the contract is correct, because non-load-bearing fields can change. The harness then either passes spuriously (if drift is in fields the assertions ignore) or fails spuriously (if drift is in fields the assertions watch). | medium | medium | Re-capture the live fixtures before each unpin attempt, per the FEAT-002 "How to capture the known-good payload" subsection. Treat the captured fixtures as a per-rollout artifact, not as a long-lived golden file. | R-03 | Sidecar WireGuard public key rotation breaks `lw-cfwg-47` silently: the panel rotates the sidecar's `wireguard_public_key` (in `bond_sidecar_point.agent_config_json`), but the client agent caches the older sidecar pubkey via `applied.json` and does not re-render the `[Peer] PublicKey` line of the wg conf, so the WG handshake silently breaks. | low | high | Include `sidecar_public_key` (and the derived `[Peer] PublicKey` line in the rendered wg conf) in the FEAT-002 diff harness assertions, per `test_cfwg_forward_47_wg_conf_render.py` and the placeholder `SIDECAR_PUBKEY_PLACEHOLDER=` substitution. | R-05 | Version pin race where the panel updater pushes a new `client_agent.py` before the diff harness has captured the new payload: the operator clears `disable_auto_update`, the panel pushes within seconds, the harness was last run against the previous panel build, and the new bytes are deployed before the harness has had a chance to validate them. | medium | high | Re-pin `disable_auto_update` if the harness has not been re-run within the same operator session as the unpin. ## Risk priorities for the next session

Not every risk in the table above carries the same urgency for the next coder agent and the next live operator. The list below ranks the eight risks into three tiers so the next session can sequence its work correctly. The tiering is informed by which risks are already realized on this branch versus which are latent.

- Tier 1 (already realized, must be resolved before any unpin attempt): R-06 manifest hash desync (the existing `test_artifact_versions_consistency.py` would fail today on this branch's working tree); R-08 sandbox-cannot-reach-host (every host-side step is currently OUT OF SCOPE and must be handed to a live operator).
- Tier 2 (latent, gated by the harness from FEAT-002): R-01 panel push regresses CFWG contract during unpin; R-04 applied.json signature staleness; R-05 version pin race during rollout.
- Tier 3 (latent, lower frequency, but high impact when triggered): R-02 fixture-vs-live drift; R-03 sidecar WG public key rotation; R-07 path-prefix shape mismatch.

Tier 1 must be cleared before any execution-side work begins. Tier 2 must be mitigated by a green harness run in the same operator session as the unpin per [`04-rollout-unpin-runbook.md`](./04-rollout-unpin-runbook.md) Section 2. Tier 3 risks survive the unpin and require ongoing test coverage; they are why the FEAT-002 fixture set must include `sidecar_public_key`, the `applied.json` shape, and the `cf_path_prefix` no-leading-slash assertion as first-class fields.
