# Unified Web Skin v2 Design

## Goal

Replace the three coexisting design systems in the web frontend with a single one: a dark, dimensional, achromatic visual system covering both the public pages and the ~40-page operator console. Ship it behind a reversible skin flag whose eventual removal is enforced by tests rather than by intent.

The aesthetic target the user set is "科技感而不庸俗" — technical without being tacky. The resulting direction, chosen by the user through a visual comparison process, is: restrained near-black skeleton, dimensionality from rendered form and layered depth, emphasis by luminance rather than hue.

## Problem

The frontend is not suffering from weak aesthetics. It is suffering from three design systems stacked in the same files, fighting each other through `!important`.

| Layer | Location | Palette | Type | Radius |
| --- | --- | --- | --- | --- |
| 1 · Glass | `operator-console.css` (702 lines, 341 `!important`) | `--bg:#f4efe5`, `--primary:#0f6d86` | Aptos / Segoe UI / PingFang TC | 18–28px, `backdrop-filter:blur(16px)` |
| 2 · Precision Grid | `signal-chamber.css` L544–692 | `--page-bg:#f3f3f0`, `--line-strong:#111111` | Segoe UI / PingFang SC | 2px, zero shadow |
| 3 · Signal Chamber | `signal-chamber.css` L694–735 | `#0a0c0b` hero, `--signal:#ef4938` | Inter / Segoe UI / PingFang SC | 5px |

`signal-chamber.css` is 735 lines and contains layers 1-era glassmorphism (L1–542), layer 2 (L544–692), and layer 3 (L694–735). `leikwan-ui.css` (65 lines, 0 `!important`) is a fourth, newer token file that layers 1 and 2 override. Across `signal-chamber.css` and `operator-console.css` there are **675 `!important` declarations**, four font stacks (including a serif, Iowan Old Style, used for the brand), and five radius specs (2 / 5 / 14 / 28 / 999px).

The failure mode is self-perpetuating: because no layer can be safely edited, each redesign is added as a new layer with higher specificity. The immediately preceding redesign (`docs/superpowers/specs/2026-07-25-signal-chamber-readable-core-web-redesign-design.md`) produced layer 3. Adding a fourth layer would repeat this. This design flattens instead.

**What makes flattening feasible:** page HTML is string-concatenated inside PHP controllers — `AdminController.php` (336 KB), `TenantController.php` (176 KB) — but it draws on a small, stable class vocabulary (~30 classes), and both page shells are centralized in `BaseController`:

- `BaseController::publicPage()` (≈ L1196–1237) — `<body class="pg-public">`, `.public-shell > .site-topbar / main.landing-stack / .page-footer`
- `BaseController::page()` (L1244) — `<body class="pg-app">`, `.shell > .topbar / .layout(.sidebar#workspace-navigation + main.content-card) / .page-footer`

Furthermore, while table scaffolds are inline (**43 `<table>` sites**: `AdminController` 30, `TenantController` 11, `BaseController` 2), every cell's *content* is generated by `PrecisionGridUi` (129 lines):

| Helper | Call sites |
| --- | --- |
| `resourceCell()` | ~24 |
| `status()` | 16 |
| `rowMenu()` | 16 |
| `normalizeView()` | 10 |
| `viewTabs()` | 8 |
| `pageHeader()`, `groupNavigation()` | 1 each (in the shell) |

So a full re-skin is reachable by rewriting the stylesheets, the two shell functions, and a handful of `PrecisionGridUi` methods — without touching the bulk of the controllers.

## Approved scope

**In scope:** All public pages (homepage, login, register, password reset, knowledgebase, health) and the entire admin/tenant console.

**Explicitly out of scope:**

- Emitting bond-style health snapshots from the `leigod_mode` / true-MPTCP data paths (see [Trace data source](#trace-column-data-source)). This is data-plane work and needs its own spec.
- A latency time-series table for RTT sparklines. Also data-plane; also its own spec.
- A Chinese webfont. A full CJK face is 3–8 MB; it is not deliverable over the wire. Chinese renders in a system stack.
- Refactoring the HTML string concatenation inside `AdminController` / `TenantController` / `ProvisioningService`. This design routes around it by keeping the class vocabulary stable.
- Introducing a frontend framework or any build step. The site stays server-rendered PHP with hand-authored CSS.

## Visual system

All values below are the locked design tokens. They live in one new file, `master/public/assets/leikwan-v2.css`, in a token layer followed by a component layer, with **zero `!important`**.

### Color

The skeleton is achromatic. Emphasis comes from luminance, not hue.

```
Shell    --ink-0 #0a0b0c    --ink-1 #101314    --ink-2 #171b1c    --ink-line #1f2425
Sheet    --paper-0 #fbfbf9  --paper-1 #f5f5f1  --paper-line #e6e6e0  --paper-rule #14171a
Text     on shell  --text-hi #f2f3f0  --text-lo #8b918b
         on sheet  --paper-hi #14171a --paper-lo #7a807b
         micro labels --micro #9aa09a
```

Semantic color is **quarantined to status contexts only** and is always triple-encoded (shape + low-saturation color + text), so it survives colorblindness, low-contrast displays, and grayscale printing:

| State | On sheet | On shell | Shape |
| --- | --- | --- | --- |
| Healthy | `#3F6B4E` | `#8FA894` | ● circle |
| Degraded | `#8A6A21` | `#B9A06A` | ▲ triangle |
| Down | `#96453A` | `#C08379` | ■ square |

No other component may use a hue. The previous `--signal:#ef4938` brand accent is retired; it collided with the danger state.

### Typography

Latin is self-hosted woff2 under `master/public/assets/fonts/`. Google Fonts is not reachable reliably from mainland China, where the end users are.

```
--font-display  "Archivo"            variable, wdth 62..125, wght 400..800
--font-body     "Archivo"            regular width only
--font-mono     "Spline Sans Mono"   400, 600 — all numerals and micro labels
--font-cjk      "PingFang SC","PingFang TC","Microsoft YaHei","Microsoft JhengHei","Noto Sans CJK SC",sans-serif
```

Rules:

- Display headings use `font-variation-settings:'wdth' 116–122` with `wght` 700–800 and tracking `-0.02em` to `-0.035em`.
- **Chinese headings render at 75% of the Latin size for the same heading level, at weight 600**, to balance against the wide, heavy Latin display face. This ratio is a token, not a per-page adjustment.
- Body copy and all table content lock to regular width. The `wdth` axis is display-only; varying it in dense tables destroys column rhythm.
- All numerals use `font-variant-numeric: tabular-nums` so values do not jitter across thousands of rows.

Inter, Roboto, Arial, and system-only stacks are not used for Latin.

### Radius, depth, rhythm, motion

**Radius** collapses from five specs to one: `3px` for the raised sheet, `0–1px` for rules, tracks and bars. The 2 / 5 / 14 / 28 / 999px specs are retired.

**Depth has exactly two sources.** All `backdrop-filter` glassmorphism is deleted.

1. *Public pages* — a rendered object: an abstract matte solid built from a radial gradient, inset shadows, a white rim light, and a cast shadow. Pure CSS/SVG, no build step, no raster asset.
2. *Console* — layered depth: the data sheet floats above the shell via
   `box-shadow: 0 18px 34px -14px rgba(0,0,0,.85), 0 0 0 1px rgba(255,255,255,.07)`.

**Rhythm:** 4px base grid. Table row height 34px (sized to carry a 20px trace bar).

**Motion:** the four existing guards are preserved verbatim and remain test-asserted — `prefers-reduced-motion`, `IntersectionObserver` gating, `document.visibilityState` gating, and DPR clamping.

## Shells

### Public shell — `BaseController::publicPage()`

Near-black throughout (`--ink-0`). A thin topbar with the wordmark and a single hairline; hero pairing the rendered object with a wide display heading; content column capped at 1180px with generous negative space; footer in mono micro labels.

### Console shell — `BaseController::page()`

Dark chrome with a floating light sheet. Shell at `--ink-1`; sidebar stays at the existing 244px rail with mono micro group labels and a 2px white bar on the active item.

**The page header (title, subtitle, primary action) stays on the dark shell; the white sheet carries data only.** This keeps the sheet's boundary clean and makes the "data is being held up" metaphor legible rather than decorative.

Below 900px the sheet goes full-bleed and the sidebar uses the existing drawer toggle JS unchanged.

## Data grid

### Ledger rules

- Header is a single `--paper-rule` hairline. No header fill, no zebra striping, no vertical rules.
- Column labels: `--font-mono` 7.5px, `0.18em` tracking, `--micro`.
- Identity column: Archivo 600 / 12.5px, with a 10px `--paper-lo` secondary line.
- Numeric columns: `--font-mono`, right-aligned, `tabular-nums`, units trailing at 9.5px `--micro`.
- Row height 34px, **no row rules**.

Removing row rules is what makes the ledger read as typography rather than as a grid, but it introduces line-slip risk on long lists. Three mitigations, all required:

1. Full-row hover lift to `--paper-1`.
2. A very faint banding rule every 8 rows.
3. `:focus-within` produces the same lift, so keyboard users get the same tracking aid as mouse users.

### Status cells

`PrecisionGridUi::status()` is the single change point for all 16 call sites. It emits shape class + low-saturation color + text label together; none of the three is optional.

### Trace column

A 132px × 20px bar placed immediately before the current-value column, on the 8 list views that use `viewTabs()`. The remaining table sites — roughly 35 of the 43 — are untouched.

Rendered server-side as 12 blocks of 5 minutes each covering a 60-minute window. No JavaScript, no build step. Present heartbeats render as a solid `--paper-line` band; gaps render as faint diagonal hatching; the final block carries the current status color. A forward with no history renders fully hatched.

Every trace carries an `aria-label` text summary (e.g. "3 interruptions in the last 60 minutes"). Without it a screen reader encounters an empty element.

The column label states what the data actually is — "节点在线 · 60 分钟" / "Node uptime · 60 min" — not a vague "trend".

**Dual-skin safety.** The trace is the one part of this design that requires new markup inside the inline tables, so it needs to be invisible under the legacy skin during migration. It is emitted by two new `PrecisionGridUi` helpers — `traceHeader()` and `traceCell($forward)` — each of which returns the complete `<th>` / `<td>` element, or an empty string when the active skin is `legacy`. The 8 call sites therefore add a helper call rather than literal markup, no column is orphaned under the legacy skin, and skin branching stays inside the helper layer.

### Trace column data source

The obvious source is wrong, and the reason matters enough to record.

`bond_leg_reputation_events` (from_state / to_state / `observed_at`, retained 7 days per `cleanup-tasks.php:320-334`) looks like the natural backing store for a per-leg state trace. It is not usable as the primary source, because **it is produced by the bond binary**:

```
wstunnel-main/leikwan-bond/src/session.rs
  → bond-leg-health-forward-*.json
  → client_agent.py:1143 load_bond_leg_reputation_snapshots()
  → heartbeat payload (client_agent.py:1432)
  → ClientAgentController.php:146 / SidecarAgentController.php:120
  → BondLegReputationService::ingestSnapshots() (L106)
```

Forwards that do not run the bond binary emit nothing into this chain. `install_forward_runtime.py:116` and `client_agent.py:3042` route `leigod_mode` down a different path, and the true-MPTCP design does not run the bond binary either. Building the trace on this source would produce a column that is blank precisely on the mode the fleet is migrating toward — a decoration that empties out over time.

**Decision: the trace is backed by `node_heartbeats`** (`schema.sql:696`), aggregated across the nodes carrying each forward.

- It is a dense, regularly-sampled series — one row per heartbeat — with a covering index `idx_node_heartbeats_node_created (node_id, created_at)`.
- It is **independent of `backend_mode`**, so coverage is total across leigod, bond, MPTCP, and CF.
- It is retained 24 hours (`cleanup-tasks.php:305-318`), comfortably more than the 60-minute window.
- It requires no new storage and no data-plane change.

The honest cost: granularity is node-level, not leg-level, and the window ceiling is 24 hours. Both are stated in the UI rather than papered over.

As an enhancement, forward **detail** pages that do run bond additionally show per-leg state events from `bond_leg_reputation_events`, where the data density justifies it.

Two adjacent series are noted but not used here: `service_endpoints.last_chain_latency_ms` / `best_latency_ms` are snapshots with no history (migration `20260526_add_mptcp_underlay_health_columns.sql`), and `traffic_usage_hourly` (`schema.sql:709`) is a real hourly series that could back a throughput trace on detail pages in a later pass.

## Skin flag and migration

### The flag

A single environment variable `LEIKWAN_SKIN` with values `legacy` | `v2`, defaulting to `legacy`. It is read in exactly two places: `BaseController::publicPage()` and `BaseController::page()`, plus the `PrecisionGridUi` trace helpers described above. No controller page code branches on it — the 8 trace call sites call a helper that decides for itself.

Authenticated administrators may override per-session with `?skin=v2`, persisted in the session. The parameter is ignored for everyone else. This is the canary mechanism: an operator can verify any page under the new skin without exposing it to users.

### Forcing functions

A parallel-skin migration is the same mechanism that produced the three existing layers: the switch gets added, and the old skin is never deleted. Four structural controls make deletion mandatory rather than optional.

1. **Legacy freeze test.** The SHA-256 of `signal-chamber.css`, `operator-console.css`, and `leikwan-ui.css` is asserted in a test. Any edit to them fails the suite. The legacy skin becomes a read-only fossil, so all new work is forced into v2 and the two skins cannot drift.
2. **Coverage manifest drives the default.** `master/tests/fixtures/skin-v2-coverage.txt` lists every page route, each marked `verified` or `pending`. A test asserts: **when no route is marked `pending`, the default value of `LEIKWAN_SKIN` must be `v2`.** Once migration completes, remaining on the legacy default turns the suite red. The cutover is compelled by the test, not by discipline.
3. **New pages cannot use the legacy skin.** A test asserts the route table and the manifest are in agreement; a route absent from the manifest fails. Since the legacy skin is frozen by (1), a newly added route can only honestly be marked `verified`.
4. **The teardown commit is a planned task,** not a follow-up: delete the flag and both read sites, delete the three legacy stylesheets, delete the legacy shell branches, delete the manifest and the tests from (1)–(3).

### Class vocabulary inventory

Before the rewrite, extract every CSS class actually emitted by the PHP controllers into a canonical list, and assert that the v2 stylesheet defines a rule for each. This converts "did I miss a class?" from a manual sweep across 40 pages into a mechanical check.

Static `class="..."` literals are extracted automatically. Class names composed at runtime (e.g. `class="badge {$variant}"`) cannot be extracted statically; those fragments live in an explicit, hand-maintained allowlist in the same fixture file, and the extractor fails on any dynamic composition it cannot attribute to an allowlist entry. This limitation is real and is why the test is a floor, not a proof.

## Testing

Fourteen test files currently reference legacy asset filenames, token literals, class names, or motion guards:

```
signal_chamber_homepage_regression_test.php        precision_grid_responsive_accessibility_test.php
readable_sheet_design_system_regression_test.php   precision_grid_public_pages_regression_test.php
precision_grid_page_templates_regression_test.php  precision_grid_design_system_regression_test.php
leikwan_ui_asset_regression_test.php               homepage_positioning_regression_test.php
focused_tenant_resource_views_regression_test.php  focused_transport_endpoints_views_regression_test.php
focused_slave_nodes_views_regression_test.php      focused_admin_resource_views_regression_test.php
all_tables_readable_sheet_regression_test.php      core_mobile_resource_rows_regression_test.php
```

These assert exact hex values, exact asset hrefs including `?v=20260725`, and exact HTML strings. A stylesheet rewrite fails them by construction. They are rewritten to contract level, which is what they should have asserted in the first place — the current form is why three design layers could accumulate while the suite stayed green: it locked names, not behavior.

Triage policy:

- **Token assertions** — assert the token *is defined*, not that it equals a specific hex. Palette changes stop producing false failures.
- **Markup assertions** — assert the *class is emitted* (e.g. `pg-status-dot` appears in the response), not that a full HTML string matches.
- **Asset assertions** — assert a versioned stylesheet is referenced, not a specific version string.
- **Motion and accessibility guards** — kept and strengthened. These are genuine contracts, not incidental strings.

New tests:

- Class vocabulary coverage (above).
- Legacy stylesheet freeze (above).
- Coverage manifest ↔ default value linkage (above).
- Status shape encoding: `status('down')` must emit both a shape class and a text label.
- Trace accessibility: every rendered trace carries a non-empty `aria-label`.

## Rollout and exit criteria

1. Land `leikwan-v2.css`, the self-hosted fonts, the two v2 shells, and the updated `PrecisionGridUi` methods behind `LEIKWAN_SKIN=legacy`. No user-visible change.
2. Rewrite the fourteen test files to contract level; add the five new tests. Suite green on both skins.
3. Walk the coverage manifest, verifying routes under `?skin=v2` and flipping `pending` → `verified`.
4. When the manifest has no `pending` rows, the linkage test forces the default to `v2`.
5. Teardown commit: flag, legacy stylesheets, legacy shells, manifest, and controls (1)–(3) all deleted.

**Done means:** one stylesheet, zero `!important`, one radius spec, one font system, one status encoding, and no code path that can render the legacy skin.
