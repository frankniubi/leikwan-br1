# Windows installer UX redesign with Inno Setup

## Summary

Replace the current IExpress-based Windows installer with an Inno Setup-based installer that behaves like a normal Windows desktop installer.

The redesigned installer must let users:

- choose `All users` or `Just for me` install mode;
- choose the installation directory;
- choose whether to create a desktop shortcut; and
- uninstall the app from the standard Windows installed-apps surface.

The installer must also preserve the repo-specific install behavior already in use:

- upgrade in place when appropriate;
- stop running app processes before replacement;
- create a backup of the previous install payload;
- write `install-manifest.json`; and
- support app-triggered self-update using a single downloaded setup EXE.

The installer branding must match the existing app executable logo. The setup EXE and wizard use the same icon asset as the current `leikwan-client-win.exe`: `LeikwanBridge.Desktop/src/LeikwanBridge.App/Resources/Icons/leikwan-host.ico`.

## Background

The current installer is generated by [scripts/build-windows-client-setup.ps1](C:/Users/frankniubi/Downloads/leikwan-br1/.claude/worktrees/windows-workflow-parity/scripts/build-windows-client-setup.ps1:1) and packaged with IExpress. It supports copying the desktop payload and helper binaries, self-elevation for `Program Files`, backup creation, manifest generation, and unconditional desktop shortcut creation.

That flow no longer matches the desired UX:

- users cannot choose install scope from a normal installer page;
- users cannot browse for an install path from a normal installer page;
- users cannot opt out of desktop shortcut creation;
- the setup EXE does not present standard Windows installer polish; and
- there is no normal uninstall entry in Windows installed-apps surfaces.

The desktop updater currently downloads `leikwan-bridge-setup-<version>.exe` into `%LOCALAPPDATA%/LeiKwan Bridge/updates/` and launches that EXE with `UseShellExecute = true` from [MainWindow.xaml.cs](C:/Users/frankniubi/Downloads/leikwan-br1/.claude/worktrees/windows-workflow-parity/LeikwanBridge.Desktop/src/LeikwanBridge.App/Views/MainWindow.xaml.cs:1). The redesign must preserve the single-EXE installer contract and will extend the app-triggered update command line so the installer knows exactly which install it is updating.

## Goals

1. Provide a normal interactive Windows installer UX.
2. Let users choose `All users` or `Just for me` install mode.
3. Let users choose the installation directory.
4. Let users choose whether to create a desktop shortcut.
5. Show the app branding as `LeiKwan Bridge | 利群會聚`, including on the welcome page.
6. Detect older installs in legacy locations and recommend migration to the newly selected location with user confirmation.
7. Provide a standard uninstall entry in Windows.
8. Preserve silent app-triggered updates that reuse the last chosen install mode, install directory, and shortcut selection.
9. Preserve the existing backup and `install-manifest.json` behavior.

## Non-goals

This redesign does not include:

- migrating to MSI or WiX;
- redesigning the runtime config/data layout under `%ProgramData%/Leikwan/ClientAgent`;
- changing the update download cache root under `%LOCALAPPDATA%/LeiKwan Bridge/updates`;
- adding repair/change flows beyond what Inno Setup provides by default;
- changing app startup registration behavior beyond what the existing app already does; or
- deleting user/runtime data during uninstall.

## Current constraints

### Installer packaging

Current packaging is IExpress-based and script-driven. The existing build script:

- stages the published app payload and helper binaries;
- generates `install.ps1` and `install.cmd`;
- self-elevates only inside the PowerShell installer script; and
- writes `artifacts/windows/leikwan-bridge-setup.exe`.

### Runtime/update contract

The updater still assumes a single setup EXE artifact. That must remain true after the redesign.

Current install-root discovery in [AppDefaults.cs](C:/Users/frankniubi/Downloads/leikwan-br1/.claude/worktrees/windows-workflow-parity/LeikwanBridge.Desktop/src/LeikwanBridge.App/AppDefaults.cs:1) defaults to `%ProgramFiles%/LeiKwan Bridge` unless `LEIKWAN_INSTALL_DIR` is set. That is not sufficient once both per-user and per-machine installs become first-class installer choices.

## Proposed design

### 1. Installer technology

Adopt Inno Setup as the Windows installer technology.

The delivered artifact remains:

- `artifacts/windows/leikwan-bridge-setup.exe`

The build flow changes from:

- generate `.sed` + `install.ps1` + IExpress package

To:

- stage payload files under `artifacts/windows/_setup_stage/`;
- compile an Inno Setup script into `artifacts/windows/leikwan-bridge-setup.exe`; and
- keep repo-specific copy/backup/manifest behavior either in native Inno script logic or a small retained helper script invoked by Inno.

### 2. Installer branding

The installer display name is:

- `LeiKwan Bridge | 利群會聚`

Branding rules:

- welcome page shows `LeiKwan Bridge | 利群會聚`;
- setup window title uses the same name;
- uninstall entry uses the same display name; and
- the setup EXE icon uses `LeikwanBridge.Desktop/src/LeikwanBridge.App/Resources/Icons/leikwan-host.ico` so it matches the current app executable logo.

The implementation should use the repo-owned icon asset directly rather than scraping resources from an already-installed EXE.

### 3. Interactive wizard flow

The interactive installer flow is:

1. Welcome page with `LeiKwan Bridge | 利群會聚` branding.
2. Install mode page with:
   - `All users`
   - `Just for me`
3. Install directory page.
4. Additional tasks page with `Create Desktop Shortcut`.
5. Migration page when an existing install is found in another location.
6. Ready page.
7. Install progress.
8. Finish page.

Expected defaults:

- `All users` default directory: `C:\Program Files\LeiKwan Bridge`
- `Just for me` default directory: `%LOCALAPPDATA%\Programs\LeiKwan Bridge`

The per-user default moves away from the legacy `%LOCALAPPDATA%\LeiKwan Bridge` path so the install root is clearly separated from the existing update-cache location under `%LOCALAPPDATA%\LeiKwan Bridge\updates`.

### 4. Install behavior

The installer keeps the existing repo-specific install semantics:

- stop the running app and helper processes associated with the target install root;
- back up the previous installed payload into a timestamped backup directory before replacement;
- copy the main app payload and helper binaries into the selected install root;
- keep helper binaries under `bin/` and preserve any required root-level compatibility copies; and
- write `install-manifest.json` with hashes and backup metadata.

The redesign should preserve the current compatibility contract for runtime binary discovery unless a later task explicitly changes the installed layout.

### 5. Install state persistence

The installer must persist stable install choices so later silent updates do not need the user to choose again.

Add a new `install-state.json` alongside `install-manifest.json` in the install root.

Minimum fields:

- `install_mode`: `all-users` or `just-for-me`
- `install_dir`
- `desktop_shortcut`: `true` or `false`
- `display_name`
- `installed_version`
- `installed_at`

Purpose of `install-state.json`:

- lets the running app discover its own installer state from `AppContext.BaseDirectory`;
- lets the installer confirm the target install identity during update flows; and
- avoids relying on transient environment variables like `LEIKWAN_INSTALL_DIR`.

Standard uninstall registration is still handled by Inno Setup. `install-state.json` is the product-specific state record for future updates and migration logic.

### 6. App-triggered silent update contract

App-triggered updates must become silent, but still reuse the previously chosen install mode, path, and shortcut selection.

Required behavior:

- the app continues to download `leikwan-bridge-setup-<version>.exe` into `%LOCALAPPDATA%/LeiKwan Bridge/updates/`;
- the app launches that EXE with `UseShellExecute = true`;
- the app now passes explicit silent-update command-line arguments rather than launching the installer with no arguments.

The silent-update launch contract uses explicit arguments passed by the app and must include:

Required arguments:

- `/VERYSILENT`
- `/NORESTART`
- `/LEIKWANUPDATE=1`
- `/LEIKWANINSTALLDIR=<current install root from AppContext.BaseDirectory>`
- `/LEIKWANINSTALLMODE=<all-users|just-for-me from install-state.json>`
- `/LEIKWANDESKTOPSHORTCUT=<1|0 from install-state.json>`

The installer must treat these arguments as authoritative for silent update targeting and must refuse to continue if they conflict with the discovered install state on disk.

Silent-update rules:

- no wizard pages are shown;
- `All users` installs must still trigger a UAC prompt when launched from a non-elevated app session;
- the installer reuses the previous install mode, install root, and shortcut selection;
- if the passed target install cannot be matched to a valid existing install state, silent update fails with a clear error instead of guessing.

This avoids a silent update accidentally targeting the wrong installation when both per-user and per-machine installs exist on the same machine.

### 7. Existing-install detection and migration

The installer must scan for existing installs in known locations before completing the wizard.

At minimum, detection includes:

- legacy per-user install root: `%LOCALAPPDATA%\LeiKwan Bridge`
- new per-user install root: `%LOCALAPPDATA%\Programs\LeiKwan Bridge`
- machine install root: `C:\Program Files\LeiKwan Bridge`

When an existing install is detected outside the currently selected target directory:

- show a migration page;
- recommend migration to the newly selected location by default; and
- explain that the installer will update shortcuts, uninstall entry, and installed program files.

If the user declines migration:

- do not force relocation; and
- upgrade the existing install in place at its current location instead of creating a second side-by-side install.

The migration page must be explicit that program files move, but runtime/config data under `%ProgramData%/Leikwan/ClientAgent` is preserved.

### 8. Desktop shortcut behavior

Desktop shortcut creation becomes an explicit installer task instead of unconditional behavior.

Rules:

- the interactive installer exposes a `Create Desktop Shortcut` checkbox;
- the selected value is persisted into `install-state.json`;
- silent updates reuse the stored value; and
- uninstall removes installer-created desktop shortcuts.

### 9. Uninstall behavior

The installer must register a standard uninstall entry in Windows installed-apps surfaces.

Scope rules:

- `All users` install: machine-scoped uninstall entry
- `Just for me` install: current-user uninstall entry

Uninstall removes:

- installed program files under the chosen install root;
- installer-created desktop shortcuts;
- uninstall registration created by Inno Setup; and
- `install-state.json` / `install-manifest.json` and related installer-owned metadata in the install root.

Uninstall does not remove:

- runtime/config/data under `%ProgramData%/Leikwan/ClientAgent`
- downloaded update cache under `%LOCALAPPDATA%/LeiKwan Bridge/updates`

This keeps uninstall safe and consistent with current runtime data ownership.

### 10. Elevation behavior

The installer should stop relying on custom PowerShell self-relaunch for the main UX path.

Expected behavior:

- interactive `All users` installs use Inno Setup’s standard elevation flow and UAC prompt;
- interactive `Just for me` installs do not require administrator rights;
- silent machine-scoped updates must still produce a UAC prompt when launched from a non-elevated app session;
- rejecting UAC aborts the install cleanly without partial success markers.

### 11. Failure handling

Failure rules:

- if required elevation is denied, abort cleanly;
- if files are locked, instruct the user to close the app and do not mark the install as successful;
- if silent update cannot uniquely validate the intended target install, abort with a clear error;
- only write successful install state after payload copy, shortcut handling, and uninstall registration complete.

### 12. Verification strategy

#### Automated verification

Required automated checks:

1. the Windows build script can compile `artifacts/windows/leikwan-bridge-setup.exe` through Inno Setup;
2. silent install works for `All users` and `Just for me` modes;
3. `Create Desktop Shortcut` on/off is honored;
4. upgrade installs still write `install-manifest.json`;
5. `install-state.json` is written with the expected fields;
6. legacy-install detection and migration decision logic are covered; and
7. silent update refuses ambiguous or invalid targets instead of guessing.

The current test harness is IExpress/CAB-specific and must be replaced with Inno-oriented verification that checks installed outputs and command-line behavior rather than extracted `.cab` contents.

#### Manual verification

Required manual checks:

1. double-clicking the setup EXE opens a normal installer wizard;
2. welcome branding shows `LeiKwan Bridge | 利群會聚`;
3. users can choose `All users` or `Just for me`;
4. users can choose the install directory;
5. users can choose whether to create a desktop shortcut;
6. an old `%LOCALAPPDATA%\LeiKwan Bridge` install triggers the migration recommendation flow;
7. the app appears in Windows installed-apps surfaces and can be uninstalled;
8. app-triggered updates run silently and reuse the previous install choices; and
9. machine-scoped updates still elevate correctly when required.

## Risks

### Silent-update target ambiguity

If the installer is launched silently without enough target information, it could update the wrong install.

Mitigation:

- require explicit install identity from the running app;
- validate against `install-state.json`; and
- fail rather than guess.

### Legacy-path migration complexity

Old per-user installs under `%LOCALAPPDATA%\LeiKwan Bridge` overlap with update-cache naming conventions and historic behavior.

Mitigation:

- keep detection rules explicit;
- separate new per-user install default under `%LOCALAPPDATA%\Programs\LeiKwan Bridge`; and
- verify migration paths manually.

### Scope drift between installer and runtime assumptions

The runtime currently defaults to `%ProgramFiles%/LeiKwan Bridge` when no override is present.

Mitigation:

- treat `install-state.json` as the canonical update/install scope record for installed apps; and
- update runtime/install-root discovery only where required to support the new installer contract.
