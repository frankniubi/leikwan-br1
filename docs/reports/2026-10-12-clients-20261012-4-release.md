## Changes

- **Android app groups (按 App 分流).** App routing has user-defined groups. Each group names a line (forward) and one of the user's nodes, so group A can leave through one node while group B leaves through another. When the selected service is Ultra, every other group line gets its own Ultra runtime and lease next to the selected one. Renewal, restart and stop cover all of them, and one line failing to renew no longer stops the others from renewing. A line that cannot start falls back to the selected node. Groups are ignored in native-outbound mode and when no node is selected.
- **Android Services list.** Each row shows `#<forward id> · <direction>` with `Listen :<port> → <target>` underneath, instead of the plan name, mode and speed limit.
- **Windows native outbound speed.** The dashboard's speed chart and traffic ring read only ordinary Ultra status files, so native outbound showed nothing. They now also read each native forward's newest lease instance under `proxy-runtime/native-usage`. Billing was never affected: the heartbeat already reported those counters (production `ultra_usage_events` for forward 180 matched the local runtime counter before the fix).
