# Release clients-20261026-5 (2026-10-26)

Ultra runtime 2026.10.26.1 with the zero-byte close window fix, published with
Windows 0.1.20.77, Windows headless 0.1.20.67, macOS arm64 1.0.60 and Android
0.2.46 (versionCode 48). Not forced: no `client_update` field, no minimum
version. Clients update only when the user accepts.

## What ships

| Component | Before | After |
|---|---|---|
| Windows app (setup) | 0.1.20.76 | **0.1.20.77** |
| Windows headless | 0.1.20.66 | **0.1.20.67** |
| macOS arm64 (DMG + update zip) | 1.0.59 | **1.0.60** (Developer ID, notarized) |
| macOS x64 | 1.0.56 | unchanged (no Intel build in this release) |
| Android APK | 0.2.45 (47) | **0.2.46 (48)**, signed v2/v3 |
| Ultra runtime, all platforms | 2026.10.12.1.06471310 | **2026.10.26.1.571600c2** |

Runtime change: `haZeroByteCloseMaxAge` 500 ms to 3 s (`haDeadStreamMaxAge`).
A clean empty relay close 1 to 3 s after the first flight now counts toward path
isolation. Evidence: forward 292, combination 53. See
`docs/reports/` and commit `9d0cc06c`.

## Not in this release

- **iOS (TestFlight).** Not built for release. The iOS workflow uploads a signed
  build to TestFlight on every non-PR run once secrets exist. Decision pending.
- **macOS Intel (x64).** Still 1.0.56 with runtime `2026.10.12.1`. Its hashes stay
  accepted. It does not receive the zero-byte fix until an Intel build is made.
- **Linux agent.** Unchanged (`2026.10.21.1`). Only the runtime moved.
- **Clients with the old runtime** keep working: their hashes are registered in the
  extra list.
