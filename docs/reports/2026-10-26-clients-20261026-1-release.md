## What changed
- Crash on TUN connect: `WindowsInterfaceEnumerator` read `IP_ADAPTER_*_ADDRESS` lists with `Next` and `lpSockaddr` swapped. The TUN adapter's DNS-eligible address produced an uncatchable AccessViolationException, which killed the client. The same bug also left panel direct-egress NIC binding silently empty on Windows.
- Orphaned sing-box after a client crash kept the TUN adapter up and cut the network. sing-box now joins a kill-on-close job on start and the job is disposed on stop.

## Runtime and attestation
- All bundled helpers are byte-identical to 0.1.20.71 (sing-box `a4476dd7…`, ultra-client `ddb8b98e…`, wstunnel, bond, uot-bond, ingress, mptcp-relay, Redirector, netfilter2, nfapi). No attestation rollover.

## Packaging
- The app folder is built self-contained (`dotnet build -c Release -r win-x64 --self-contained true`). The first attempt used a framework-dependent build, so the setup had no .NET runtime. It ran only on machines with the .NET 8 runtime installed, which hid the problem during the local test. The stage now matches 0.1.20.71 file for file (263 files; only `LeikwanBridge.App.dll` and `LeikwanBridge.Core.dll` differ).
- `build-windows-client-setup.ps1` copies every non-exe file from the `dotnet build` output, so the build step must use the self-contained flags.
