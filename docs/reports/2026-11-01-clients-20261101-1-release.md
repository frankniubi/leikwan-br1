Runtime change (release/quota-refill-20261101, fix commit `b8d5f402`):

- A large download drains the local quota slice faster than the panel's
  renewal cadence refills it (the slice floor assumed 1000 Mbps; the fleet
  now tops ~2500 Mbps). The runtime then ended every active TCP stream with
  stage=policy reason=quota_exhausted — the reported "large downloads
  interrupt" on native outbound and ordinary Ultra alike.
- Runtime: TCP copies pause on a drained slice (`WaitQuota`, 120 s bound)
  instead of tearing the stream down; revocation/expiry still ends the copy
  immediately. UDP keeps the immediate drop. status.json publishes
  `quota_remaining_bytes`.
- Hosts: renew the native lease when the published slice falls below 2 GiB;
  quota_exhausted stream ends drive the failure-driven Ultra renewal.
- Panel: quota-slice floor 2 → 3 renewal intervals, unlimited-rate
  assumption 1000 → 2500 Mbps (unlimited forwards now receive the whole
  remaining quota), commit `b8d5f402` on the release branch.
