## Change

- **Native outbound custom DNS rides UDP.** Every native scope resolves destinations before the SOCKS handoff, so the configured DNS server is the only path for all named traffic. On an unrestricted global route it was still TCP to the custom server (e.g. 8.8.8.8:53) through the relay. On 2026-10-13 around 13:14 (UTC+8) a user's browsing stopped while Telegram (fixed IPs) kept working. Reproduced at 13:24: 28 of 30 TCP DNS queries through the native SOCKS port hit EOF ~130 ms after the query, then recovered a minute later. The same relay answered UDP DNS 27 of 30. Custom DNS now uses `udp` on every native scope; non-native profiles keep `tcp`.
