Forward Lines API · v1专线 API 文档

租户通过 API 管理自己服务下的转发规则（forward）：查询可用线路、创建、修改、删除。LeiKwan 只做数据包转发——节点、线路组合、入口、隧道凭据等都不是租户资源，不会出现在 API 里。

Base URL  https://<panel-host>

§1认证

header
Authorization: Bearer <user-api-token>
  • 只接受 Authorization: Bearer，不接受 query string 里的 token。
  • 账号必须是租户（role=tenant）且处于启用状态，否则统一返回 401 user_auth_failed。
  • 目前 token 由运营方发放，租户面板暂无查看或轮换入口。请勿在日志中打印 token。

§2通用约定

项规则
编码请求与响应均为 JSON（UTF-8）
写请求必须 Content-Type: application/json，否则 415；请求体上限 16 KiB，否则 413
类型严格类型：端口、ID 必须是 JSON 整数，不能是字符串
未知字段任何未定义的顶层或嵌套字段 → 422 unknown_fields
缓存成功响应带 Cache-Control: no-store、X-Content-Type-Options: nosniff
版本控制单资源响应带 ETag: "forward-{id}-r{revision}"；PATCH / DELETE 必须用 If-Match 精确匹配（不支持 W/、*）
幂等创建必须带 Idempotency-Key（8–64 位，字符集 [A-Za-z0-9._:-]）

§3路由一览

方法路径必需头结果
GET/api/v1/user/services/{service_id}/forward-optionsBearer可选线路、传输方式、配额、权限
GET/api/v1/user/services/{service_id}/forwardsBearer该服务下所有生效中的转发
POST/api/v1/user/services/{service_id}/forwardsBearer、Content-Type、Idempotency-Key创建（201）或幂等重放（200）
GET/api/v1/user/forwards/{forward_id}Bearer单条转发 + ETag
PATCH/api/v1/user/forwards/{forward_id}Bearer、Content-Type、If-Match修改，返回新 ETag
DELETE/api/v1/user/forwards/{forward_id}Bearer、If-Match软删除，204 空响应

路径中的 ID 必须是正整数。格式不对、不属于你、已删除，一律返回 404（service_not_found / forward_not_found），不区分原因。

§6创建

POST/api/v1/user/services/42/forwards
request
Authorization: Bearer <token>
Content-Type: application/json
Idempotency-Key: create-fwd-20261007-01

{
  "route_id": 14,
  "listen_port": null,
  "transport": "tcp",
  "target": {"source": "manual", "host": "203.0.113.10", "port": 443}
}
字段必填规则
route_id是正整数，必须是 forward-options 返回的线路
listen_port是（键必须存在）1–65535 整数，或 null 表示自动分配
transport是tcp / udp / tcp+udp
target非 native 时必填见下
native_outbound否默认 false

target

  • manual：{"source":"manual","host":"…","port":N}。host 为 ASCII IPv4 / IPv6 / 域名（≤ 253 字符），不允许 scheme、userinfo、路径、空白、控制字符、IPv6 zone。
  • service_ip：{"source":"service_ip","service_id":43,"port":8443}。service_id 必须是你名下的服务，不接受 host。

保留地址会被拒绝。目标由平台节点代为连接，因此以下地址返回 422，fields: {"target.host": "reserved_range"}：环回 127.0.0.0/8、::1；链路本地 169.254.0.0/16（含云元数据 169.254.169.254）；0.0.0.0；localhost / *.localhost。私有网段 10/8、172.16/12、192.168/16 仍可用于你自己的后端。

示例

curl
curl -sS -X POST "https://panel.example.test/api/v1/user/services/42/forwards" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: create-fwd-20261007-01" \
  -H "Content-Type: application/json" \
  -d '{"route_id":14,"listen_port":null,"transport":"tcp","target":{"source":"manual","host":"203.0.113.10","port":443}}'
powershell
$body = @'
{"route_id":14,"listen_port":null,"transport":"tcp+udp",
 "target":{"source":"manual","host":"203.0.113.10","port":443}}
'@
Invoke-RestMethod -Method Post `
  -Uri "https://panel.example.test/api/v1/user/services/42/forwards" `
  -Headers @{ Authorization = "Bearer $TOKEN"; 'Idempotency-Key' = 'create-fwd-20261007-01' } `
  -ContentType 'application/json' -Body $body

成功返回 201，带 Location: /api/v1/user/forwards/{id} 与 ETag，body 为 {"ok":true,"forward":{…}}。

校验顺序

决定你先看到哪个错误：

认证→服务归属→服务有效（含到期）→功能权限→Content-Type→体积→字段校验→Idempotency-Key→幂等重放→配额→线路 / 节点可用性

§7列表与详情

GET/api/v1/user/services/42/forwards
GET/api/v1/user/forwards/123

列表返回 {"ok":true,"forwards":[…]}，只包含生效中的转发，不带 ETag。修改或删除前，请先 GET 详情拿到 ETag。

§8修改

PATCH/api/v1/user/forwards/123
request
Authorization: Bearer <token>
Content-Type: application/json
If-Match: "forward-123-r3"

{
  "transport": "tcp+udp",
  "target": {"source": "manual", "host": "backend.example.test", "port": 8443}
}
  • 可改字段：route_id、listen_port、transport、target（可部分）、native_outbound（仅关闭）。至少一个字段。
  • 成功返回新资源和新 ETag，例如 "forward-123-r4"。
  • 结构性修改——改 route_id、target.source、target.service_id、native_outbound、实际改变 transport，或 listen_port: null 重新分配——会重新编排节点；校验失败时原子回滚，线路不可用返回 409 route_unavailable。
  • 非结构性修改——只改 target 的 host / port，或指定非零 listen_port——走轻量更新路径，但仍会重建该转发的端点，请勿高频调用。
  • 切换 manual ↔ service_ip 必须在同一个 patch 中带齐 source 与 service_id / host。

§9Native Outbound（设备侧出站）

承载在客户端设备上运行，而不是平台入口。创建时不传 target，由服务端自动指定：

request body
{"route_id": 14, "listen_port": null, "transport": "tcp+udp", "native_outbound": true}
条件不满足时
线路为 Ultra 组合，且 transport 为 tcp+udp422 native_outbound_requires_ultra_tcp_udp
套餐开启 allow_native_outbound403 native_outbound_not_allowed
线路带方向422 native_outbound_direction_missing
同服务下该方向未被其他生效的 native 转发占用409 native_direction_conflict
  • 关闭：PATCH {"native_outbound": false, "target": {"source":"manual","host":"…","port":N}}。
  • 对已有转发开启 native 不是 v1 PATCH 操作，请新建转发或使用面板表单。native 转发的 PATCH 带 target 字段会返回 422，fields: {"target": "forbidden_for_native_outbound"}。

§10删除

DELETE/api/v1/user/forwards/123
request
Authorization: Bearer <token>
If-Match: "forward-123-r4"
  • 成功返回 204 空响应，为软删除（保留墓碑记录）；ETag 过期时不会删除任何东西。
  • 已删除记录计入每个服务的历史保留上限（默认 512 条）。达到上限后创建返回 409 forward_storage_quota_exceeded，需要联系运营归档。请勿循环创建 / 删除。

§11重试与并发

  • 读请求可以随意重试。
  • 创建超时：用同一个 Idempotency-Key 和相同的 JSON 重试，服务端返回原资源（200），不会重复创建。
  • 同一个 key 发送不同内容 → 409 idempotency_conflict；原资源已删除 → 409 idempotency_resource_inactive。
  • PATCH / DELETE 收到 412 forward_version_conflict：重新 GET 详情，确认后用新 ETag 再操作，不要原样重放。
  • 并发创建会锁定服务行并复核配额，不会超出 forward_limit。

§12错误码

error envelope
{
  "ok": false,
  "error": {
    "code": "validation_failed",
    "message": "The forward request is invalid.",
    "fields": {"target.port": "out_of_range"}
  }
}

unknown_fields 的 fields 是数组（如 ["target.foo"]），validation_failed 的 fields 是对象。

§13旧版接口（已废弃）

/api/user/services/{id}/forwards、/api/user/forwards/{id}（PUT / DELETE）、/api/user/forwards/{id}/client-config、/api/user/services/{id}/regenerate-client-token 仍可用但已废弃，响应带 Deprecation: true，错误格式为 {"error":code,"details":{…}}，没有 ETag 和幂等保护。新集成请只使用 v1。
