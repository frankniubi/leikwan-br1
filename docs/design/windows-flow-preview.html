现在的动线：4 步，跨 4 个页面

1 节点导入或编辑节点（节点页）
→
2 服务把节点配对到服务（服务页）。节点页里还有一套配对。
→
3 代理选服务、选模式、点连接。连接设置默认折叠。
→
4 仪表盘逐条“启动”服务。这和代理页的“连接”是两套开关。

现在的问题（已对照代码确认）

  • 配对入口有两处。服务页的“转发配对”和节点页的“节点”列表，绑定的是同一份 ProxyForwardRows，用户要在两个页面之间来回找。
  • 节点编辑入口有两处。节点页有编辑器；代理页的“连接设置”里还有一套手动填写（ProxyManualSection）。它在 XAML 里默认折叠，代码里没有让它显示的路径（只找到 XAML 里一处引用），所以按“新建节点”展开后，看不到编辑字段。
  • “连接设置”默认折叠（ProxyNodeEditorExpander），但绕过大陆 IP、DNS、本地端口都在里面，是每次连接都会碰到的选项。
  • 仪表盘的“启动”只拉起转发监听（ApplyForward），代理页的“连接”会在转发之上再启动 sing-box。界面上两者都是按钮，用户分不清。

建议的动线：3 个固定页面，原生出口按需出现

1 服务与节点导入节点、编辑节点、把节点配对到服务，全部在同一页完成。配对只保存配置，不发起连接。
→
2 连接页首一句说明（中英文）。然后一页包办：选服务、选模式、连接，以及绕过大陆 IP、DNS、本地端口、游戏。整页不折叠。
→
3 仪表盘上面四张卡：套餐、用量、速率限制、当前归属省份。下面是老版本的转发控制列表：启动、停止、转发详情、全部启动和全部停止。
原生出口（仅在有时显示）从左侧导航拆出来，单独一项。只有套餐分配了原生出口时才出现，没有时整项隐藏。它使用套餐出口，不是用户自己的节点，所以不放进节点列表，也不混进“连接”。

已按你的反馈确定

  • 服务与节点合并为一页。
  • “连接设置”并入“连接”，整页不折叠，不再单独叫“连接设置”。
  • “原生出口”拆成导航里的独立一项，只在有原生出口时显示。
  • “代理”更名为“连接”。
  • 仪表盘顶部只放套餐、用量、速率限制、当前归属省份四张卡，不展示代理连接状态和速率图表。
  • 仪表盘下方保留老版本的转发控制列表（启动、停止、转发详情、全部启动和全部停止）。
  • “连接”页顶部加一句说明：该功能非必须，连接终端由使用者提供，可用其他软件往 127.0.0.1 连接，或从局域网连接。

仍需你确认的 3 个决定

  1. 配对是否改为即时保存，去掉“保存配对”按钮？
    建议：是。 预览里改下拉框就保存，并给一个“已自动保存”的提示。
  2. 服务上的“本地监听”开关要不要保留？它对应“其他代理软件指向 127.0.0.1”的场景。仪表盘的启动/停止和它是同一个开关，两处入口要留一处还是都留。
    建议：保留，作为服务卡上的次要开关，不和“连接”混在一起。
  3. 侧栏底部的连接状态圆点要不要去掉？它在每个页面都显示，仪表盘本身已经不展示连接状态。
    建议：保留。 连接在别的页面时，它是唯一能一眼看到连接状态的地方。

数据来源（实现前要核对）

  • 当前归属省份：后端已有，用来限制登录地区。这个版本先在 Windows 上只读展示，不在客户端计算。
  • 套餐、用量、速率限制：预览里是示例数字。我还没有核对面板是否已经把这三项下发给 Windows 客户端，实现前需要确认接口。
