你將完成什麼

你會依應用程式所在位置選擇正確的用戶端位址，透過轉發送出要求，並分清面板狀態和目標應用程式確實收到流量的證明。

開始前準備

  • 記下轉發的本機連接埠。
  • 確認用戶端有最近同步，轉發顯示 Running。
  • 確認應用程式是在用戶端裝置，還是在另一台裝置執行。
  • 使用能理解協定的測試；只確認 TCP 連接埠開啟，不代表 HTTP、SSH、資料庫或遊戲要求能正確運作。

決定使用哪個位址的關鍵，是應用程式在哪裡執行。同一台裝置使用迴送位址；跨裝置只能透過可連到的 Windows 或 Linux 用戶端主機，且可能需要調整網路存取規則。Android 仍維持只監聽迴送位址，除非另有核准且支援的架構。

  1. 應用程式在用戶端裝置時，填入 127.0.0.1 和轉發的本機連接埠。
  2. 其他裝置要透過 Windows 或 Linux 用戶端連線時，填入可連到的 Windows 或 Linux 用戶端主機位址和相同連接埠。
  3. 跨裝置使用時，只在主機防火牆開放該連接埠。
  4. 若使用雲端主機，也要在安全群組開放相同連接埠。
  5. 用戶端位於路由器後方時，只有在網路管理者核准後才設定 NAT。
  6. 不要把 Android 描述成跨裝置監聽服務；除非有核准的支援設計，否則它只監聽迴送位址。
  7. 用實際應用協定送出要求。
  8. 檢查回應；若能查看目標服務記錄，也要確認要求確實抵達。

如何確認成功

應用程式透過用戶端位址和本機連接埠取得預期回應。最有力的證明是目標服務記錄中有對應要求。Connected、Running 和本機連接埠開啟都很有用，但任何一項都不能單獨證明目標應用程式已處理要求。

如果沒有成功

請先停止開放大範圍防火牆規則，也不要假設任何公用 IP 都能使用。重新確認是同裝置或跨裝置、核對本機連接埠，並從目標服務所在主機測試服務。接著查看診斷，或向支援提供錯誤、時間、用戶端平台和轉發名稱，但不要附上機密。
