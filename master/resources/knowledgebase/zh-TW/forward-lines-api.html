這篇文件適合誰

如果你想用自己的程式或腳本管理轉發規則——批次建立、依需要切換線路、接入你自己的系統——就使用專線 API。日常手動操作直接在控制台完成即可，不需要 API。

API 只管理「轉發規則」本身：使用哪條線路、本機監聽哪個連接埠、轉發到哪個目標。節點、線路組合、通道憑證由平台負責，不會出現在 API 裡。實際連線仍由 LeiKwan 用戶端取得設定後建立。

認證

Authorization: Bearer <你的 API 令牌>
  • 只接受請求標頭裡的 Bearer 令牌，不接受寫在網址裡的令牌。
  • API 令牌在控制台「帳戶安全 → API 令牌」中查看，也可以在那裡重設；重設後舊令牌立即失效。請像密碼一樣保管，不要印到日誌裡。
  • API 令牌不是「用戶端」頁面上的用戶端令牌（Agent Token）。用用戶端令牌呼叫 API 會回傳 401 user_auth_failed。
  • 令牌無效或帳號已停用時，一律回傳 401 user_auth_failed。

通用規則

項目規則
位址https://v3.leikwanhost.com
格式請求與回應都是 JSON（UTF-8）
寫入請求必須帶 Content-Type: application/json，否則回傳 415；請求內容不超過 16 KiB，否則回傳 413
資料型別連接埠與 ID 必須是 JSON 數字，不能寫成字串

版本號單條轉發的回應帶 ETag，例如 "forward-123-r3"；修改與刪除必須用 If-Match 帶上它
防重複建立建立時必須帶 Idempotency-Key，8–64 個字元，只能使用英文字母、數字與 . _ : -

服務 ID 可以在控制台「服務」頁面看到。路徑裡的 ID 寫錯、不屬於你、或轉發已刪除，一律回傳 404，不區分具體原因。

第一步：查詢可用線路

GET /api/v1/user/services/42/forward-options
{
  "ok": true,
  "transports": ["tcp", "udp", "tcp+udp"],
  "forward_limit": 64,
  "active_forward_count": 2,
  "capabilities": {
    "allow_manage_forwards": true,
    "allow_delete_forwards": true
  },
  "routes": [
    {
      "id": 14,
      "label": "滬日專線",
      "description": "上海 → 東京",
      "badge": "stable",
      "transports": {
        "tcp":     {"available": true,  "healthy_node_count": 2, "unavailable_reason": null},
        "udp":     {"available": false, "healthy_node_count": 0, "unavailable_reason": "no_healthy_nodes"},
        "tcp+udp": {"available": true,  "healthy_node_count": 2, "unavailable_reason": null}
      }
    }
  ]
}
  • routes 只包含你的套餐可以使用的線路，建立轉發時使用其中的 id。
  • forward_limit 是該服務最多可同時生效的轉發條數，active_forward_count 是目前已使用的條數。
  • unavailable_reason 可能是 route_unavailable、no_healthy_nodes、transport_unavailable 或 not_configured。

建立轉發

POST /api/v1/user/services/42/forwards
Authorization: Bearer <你的 API 令牌>
Content-Type: application/json
Idempotency-Key: create-fwd-20261007-01

{
  "route_id": 14,
  "listen_port": null,
  "transport": "tcp",
  "target": {"source": "manual", "host": "203.0.113.10", "port": 443}
}
欄位必填說明
route_id是第一步查到的線路 ID
listen_port是用戶端裝置上的本機監聽連接埠，1–65535；填 null 自動分配
transport是tcp、udp 或 tcp+udp
target是轉發目標，見下方說明（Native Outbound 轉發除外）
native_outbound否預設 false，見「Native Outbound」一節

轉發目標

  • 手動填寫：{"source": "manual", "host": "…", "port": 443}。host 可以是 IPv4、IPv6 或網域名稱，最長 253 個字元，不能帶 http://、路徑或空白。
  • 指向你的另一個服務：{"source": "service_ip", "service_id": 43, "port": 8443}。service_id 必須是你名下的服務，此時不要填 host。

以下目標位址會被拒絕。轉發目標由平台節點去連線，所以本機位址、鏈路本地位址與雲端中繼資料位址都不允許：127.0.0.0/8、::1、169.254.0.0/16（含 169.254.169.254）、0.0.0.0、localhost。此時回傳 422，fields 裡是 "target.host": "reserved_range"。內網位址 10.x、172.16–31.x、192.168.x 可以正常使用。

curl 範例

curl -sS -X POST "https://v3.leikwanhost.com/api/v1/user/services/42/forwards" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: create-fwd-20261007-01" \
  -H "Content-Type: application/json" \
  -d '{"route_id":14,"listen_port":null,"transport":"tcp","target":{"source":"manual","host":"203.0.113.10","port":443}}'

建立成功回傳 201，回應標頭裡有 Location 與 ETag，回應內容是 {"ok": true, "forward": {…}}。

查看轉發

GET /api/v1/user/services/42/forwards
GET /api/v1/user/forwards/123

列表只回傳生效中的轉發，而且不帶 ETag。要修改或刪除某條轉發，請先查看它的詳情取得 ETag。單條轉發的格式如下：

{
  "id": 123,
  "service_id": 42,
  "route": {"id": 14, "label": "滬日專線"},
  "listen_port": 11024,
  "transport": "tcp",
  "native_outbound": false,
  "native_direction": null,
  "target": {"source": "manual", "host": "203.0.113.10", "port": 443, "service_id": null},
  "ingress": {"host": null, "port": null},
  "state": "active",
  "endpoint_count": 1,
  "active_endpoint_count": 1,
  "revision": 3,
  "created_at": "2026-10-07 03:00:00",
  "updated_at": "2026-10-07 03:05:00"
}
  • revision 每修改一次加 1，ETag 就是 "forward-{id}-r{revision}"。
  • ingress 是保留欄位，目前固定為 null，請不要依賴它。連線資訊由用戶端自動取得。

修改轉發

PATCH /api/v1/user/forwards/123
Authorization: Bearer <你的 API 令牌>
Content-Type: application/json
If-Match: "forward-123-r3"

{
  "transport": "tcp+udp",
  "target": {"source": "manual", "host": "backend.example.com", "port": 8443}
}
  • 可以修改 route_id、listen_port、transport、target（可以只改其中一部分），以及關閉 native_outbound。至少要帶一個欄位。
  • 修改成功後回傳新的轉發與新的 ETag。
  • 換線路、換傳輸方式、改目標類型、或把 listen_port 改成 null 重新分配時，平台會重新安排節點。若線路暫時不可用，回傳 409 route_unavailable，原本的轉發保持不變。
  • 從手動目標改成指向服務（或反過來）時，要在同一次請求裡帶齊 source 與 service_id（或 host）。
  • 每次修改都會重建這條轉發的連線，請不要高頻呼叫。

刪除轉發

DELETE /api/v1/user/forwards/123
Authorization: Bearer <你的 API 令牌>
If-Match: "forward-123-r4"
  • 刪除成功回傳 204，沒有回應內容。ETag 不一致時不會刪除任何東西。
  • 每個服務最多保留 512 條已刪除紀錄，超過後無法再建立轉發（回傳 409 forward_storage_quota_exceeded），需要聯絡客服清理。請不要反覆建立再刪除。

Native Outbound（裝置端出站）

Native Outbound 轉發由你的裝置直接出站，而不是經過平台入口。建立時不需要填 target：

{"route_id": 14, "listen_port": null, "transport": "tcp+udp", "native_outbound": true}
條件不符合時回傳
線路支援 Native Outbound，而且 transport 是 tcp+udp422 native_outbound_requires_ultra_tcp_udp
你的套餐開啟了 Native Outbound403 native_outbound_not_allowed
線路設定了方向422 native_outbound_direction_missing
同一個服務裡，這個方向還沒有其他 Native Outbound 轉發409 native_direction_conflict

要關閉 Native Outbound，用 PATCH 送出 {"native_outbound": false, "target": {"source": "manual", "host": "…", "port": …}}。要把一般轉發改成 Native Outbound，請新建一條，或在控制台裡修改。

逾時重試與並行

  • 查詢類請求可以隨意重試。
  • 建立請求逾時沒收到結果時，用同一個 Idempotency-Key 與完全相同的內容重試，會回傳原本那條轉發（200），不會重複建立。
  • 同一個 Idempotency-Key 送出不同內容，回傳 409 idempotency_conflict；原本那條已被刪除，回傳 409 idempotency_resource_inactive。
  • 修改或刪除收到 412 forward_version_conflict，代表轉發已被改過：重新查看詳情，確認後用新的 ETag 再操作。
  • 同時送出多個建立請求也不會超出 forward_limit。

錯誤碼

出錯時一律回傳：

{
  "ok": false,
  "error": {
    "code": "validation_failed",
    "message": "The forward request is invalid.",
    "fields": {"target.port": "out_of_range"}
  }
}

validation_failed 的 fields 是「欄位 → 原因」的物件；unknown_fields 的 fields 是多餘欄位名稱的清單，例如 ["target.foo"]。

HTTP錯誤碼含義
401user_auth_failed令牌無效或帳號已停用
403feature_denied_manage_forwards、feature_denied_delete_forwards套餐不允許這個操作
403native_outbound_not_allowed套餐未開啟 Native Outbound
404service_not_found、forward_not_found不存在、不屬於你或已刪除
409service_inactive服務已停用或已到期
409forward_quota_exceeded生效轉發數已達上限
409forward_storage_quota_exceeded已刪除紀錄達到上限
409idempotency_conflict、idempotency_resource_inactive見「逾時重試與並行」
409route_unavailable線路目前不可用
409native_direction_conflict該方向已有 Native Outbound 轉發
412forward_version_conflictIf-Match 與目前版本不一致
413request_too_large請求內容超過 16 KiB
415unsupported_media_type不是 application/json
422validation_failed、unknown_fields欄位不合法，或有多餘欄位
422idempotency_key_invalidIdempotency-Key 格式不對
422forward_route_not_allowed、forward_route_has_no_enabled_combination線路不在你的套餐內，或線路暫未開放
422native_outbound_requires_ultra_tcp_udp、native_outbound_direction_missing線路不支援 Native Outbound
428idempotency_key_required、precondition_required缺少 Idempotency-Key 或 If-Match
500operation_failed平台內部錯誤，請稍後重試或聯絡客服
