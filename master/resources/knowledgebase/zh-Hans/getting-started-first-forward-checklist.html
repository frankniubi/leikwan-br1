你将完成什么

你将从已生效的套餐创建第一条转发，只填写表单中看得见的目标和传输选项，并记下应用后续连接所需的本地端口。

开始前准备

  • 确认套餐或服务状态为有效。
  • 准备目标服务的主机名或 IP 地址。
  • 确认目标端口，以及应用使用 TCP、UDP 还是两者。
  • 不要猜测表单之外的内部设置。

操作步骤

flowchart TD
accTitle: 第一条转发表单路径
accDescr: 打开有效套餐，选择转发线路，填写目标和传输方式，保存后等待预配完成并记下系统分配的本地端口。
A[打开有效套餐] --> B[选择 Forward Route]
B --> C[填写 Target Host 和 Target Port]
C --> D[选择 Transport]
D --> E[保存]
E --> F[等待转发可用]
F --> G[记下分配的本地端口]

第一张表单只需要线路方案、目标地址、目标端口、本地端口偏好和传输类型。保存会启动预配流程，系统分配的本地端口是下一步连接客户端时要使用的值。

  1. 打开已生效的服务，选择 Create Forward。
  2. 在 Forward Route 中选择系统提供的线路方案。
  3. 在 Target Host 填写目标主机名或 IP。
  4. 在 Target Port 填写目标服务端口。
  5. 没有指定安全端口时，将 Local Listen Port 留空，让系统分配本地端口。
  6. 在 Transport 中为仅使用 TCP 的应用选择 TCP。
  7. 应用同时需要两种传输时选择 TCP + UDP，仅使用 UDP 时才选择 UDP。
  8. 选择 Create Forward 完成保存。
  9. 等待预配完成，再从转发卡片记下系统分配的本地端口。

如何确认成功

新转发卡片应显示预期的目标和本地端口。保存记录、预配完成、客户端最近同步、显示 Running 和应用成功是五个不同检查点；先等待配置可用，再在客户端同步后验证真实请求。

如果没有成功

先停止猜测隐藏选项。如果没有可选的 Forward Route，或目标地址不确定，请确认套餐有效，只修正上述可见字段，并联系管理员发布合适的线路方案。
