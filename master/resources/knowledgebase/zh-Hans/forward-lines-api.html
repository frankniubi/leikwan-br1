这篇文档适合谁

如果你想用自己的程序或脚本管理转发规则——批量创建、按需切换线路、接入你自己的系统——就使用专线 API。日常手动操作直接在控制台完成即可，不需要 API。

API 只管理“转发规则”本身：用哪条线路、本地监听哪个端口、转发到哪个目标。节点、线路组合、隧道凭据由平台负责，不会出现在 API 里。真正的连接仍由 LeiKwan 客户端拉取配置后建立。

认证

Authorization: Bearer <你的 API 令牌>
  • 只接受请求头里的 Bearer 令牌，不接受写在网址里的令牌。
  • API 令牌在控制台「账户安全 → API 令牌」中查看，也可以在那里重置；重置后旧令牌立即失效。请像密码一样保管，不要打印到日志里。
  • API 令牌不是「客户端」页面上的客户端令牌（Agent Token）。用客户端令牌调用 API 会返回 401 user_auth_failed。
  • 令牌无效或账号已停用时，统一返回 401 user_auth_failed。

通用规则

项目规则
地址https://v3.leikwanhost.com
格式请求和响应都是 JSON（UTF-8）
写请求必须带 Content-Type: application/json，否则返回 415；请求体不超过 16 KiB，否则返回 413
数据类型端口和 ID 必须是 JSON 数字，不能写成字符串
多余字段出现文档以外的字段时返回 422 unknown_fields
版本号单条转发的响应带 ETag，形如 "forward-123-r3"；修改和删除必须用 If-Match 带上它
防重复创建创建时必须带 Idempotency-Key，8–64 位，只能用字母、数字和 . _ : -

接口一览

方法路径作用
GET/api/v1/user/services列出你名下的服务和它们的服务 ID
GET/api/v1/user/services/{服务ID}/forward-options查询可用线路、传输方式和配额
GET/api/v1/user/services/{服务ID}/forwards列出该服务下生效中的转发
POST/api/v1/user/services/{服务ID}/forwards创建转发
GET/api/v1/user/forwards/{转发ID}查看单条转发和它的 ETag
PATCH/api/v1/user/forwards/{转发ID}修改转发
DELETE/api/v1/user/forwards/{转发ID}删除转发

服务 ID 可以调用 GET /api/v1/user/services 获取，也列在控制台「账户安全」页的 API 令牌下方，以及每个服务的详情页里。它不是「客户端」页面上的客户端 ID，也不是商城服务编号；用错 ID 会得到 404 service_not_found。路径里的 ID 写错、不属于你、或转发已删除，都统一返回 404，不区分具体原因。

第一步：查询可用线路

GET /api/v1/user/services/42/forward-options
{
  "ok": true,
  "transports": ["tcp", "udp", "tcp+udp"],
  "forward_limit": 64,
  "active_forward_count": 2,
  "capabilities": {
    "allow_manage_forwards": true,
    "allow_delete_forwards": true
  },
  "routes": [
    {
      "id": 14,
      "label": "沪日专线",
      "description": "上海 → 东京",
      "badge": "stable",
      "transports": {
        "tcp":     {"available": true,  "healthy_node_count": 2, "unavailable_reason": null},
        "udp":     {"available": false, "healthy_node_count": 0, "unavailable_reason": "no_healthy_nodes"},
        "tcp+udp": {"available": true,  "healthy_node_count": 2, "unavailable_reason": null}
      }
    }
  ]
}
  • routes 只包含你的套餐可以使用的线路，创建转发时用其中的 id。
  • forward_limit 是该服务最多可同时生效的转发条数，active_forward_count 是当前已用的条数。
  • unavailable_reason 可能是 route_unavailable、no_healthy_nodes、transport_unavailable 或 not_configured。

创建转发

POST /api/v1/user/services/42/forwards
Authorization: Bearer <你的 API 令牌>
Content-Type: application/json
Idempotency-Key: create-fwd-20261007-01

{
  "route_id": 14,
  "listen_port": null,
  "transport": "tcp",
  "target": {"source": "manual", "host": "203.0.113.10", "port": 443}
}
字段必填说明
route_id是第一步查到的线路 ID
listen_port是客户端设备上的本地监听端口，1–65535；填 null 自动分配
transport是tcp、udp 或 tcp+udp
target是转发目标，见下方说明（Native Outbound 转发除外）
native_outbound否默认 false，见「Native Outbound」一节

转发目标

  • 手动填写：{"source": "manual", "host": "…", "port": 443}。host 可以是 IPv4、IPv6 或域名，最长 253 个字符，不能带 http://、路径或空格。
  • 指向你的另一个服务：{"source": "service_ip", "service_id": 43, "port": 8443}。service_id 必须是你名下的服务，这时不要填 host。

以下目标地址会被拒绝。转发目标由平台节点去连接，所以本机地址、链路本地地址和云元数据地址都不允许：127.0.0.0/8、::1、169.254.0.0/16（含 169.254.169.254）、0.0.0.0、localhost。这时返回 422，fields 里是 "target.host": "reserved_range"。内网地址 10.x、172.16–31.x、192.168.x 可以正常使用。

curl 示例

curl -sS -X POST "https://v3.leikwanhost.com/api/v1/user/services/42/forwards" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: create-fwd-20261007-01" \
  -H "Content-Type: application/json" \
  -d '{"route_id":14,"listen_port":null,"transport":"tcp","target":{"source":"manual","host":"203.0.113.10","port":443}}'

创建成功返回 201，响应头里有 Location 和 ETag，响应体是 {"ok": true, "forward": {…}}。

查看转发

GET /api/v1/user/services/42/forwards
GET /api/v1/user/forwards/123

列表只返回生效中的转发，并且不带 ETag。要修改或删除某条转发，先查看它的详情拿到 ETag。单条转发的格式如下：

{
  "id": 123,
  "service_id": 42,
  "route": {"id": 14, "label": "沪日专线"},
  "listen_port": 11024,
  "transport": "tcp",
  "native_outbound": false,
  "native_direction": null,
  "target": {"source": "manual", "host": "203.0.113.10", "port": 443, "service_id": null},
  "ingress": {"host": null, "port": null},
  "state": "active",
  "endpoint_count": 1,
  "active_endpoint_count": 1,
  "revision": 3,
  "created_at": "2026-10-07 03:00:00",
  "updated_at": "2026-10-07 03:05:00"
}
  • revision 每修改一次加 1，ETag 就是 "forward-{id}-r{revision}"。
  • ingress 是保留字段，目前固定为 null，请不要依赖它。连接信息由客户端自动获取。

修改转发

PATCH /api/v1/user/forwards/123
Authorization: Bearer <你的 API 令牌>
Content-Type: application/json
If-Match: "forward-123-r3"

{
  "transport": "tcp+udp",
  "target": {"source": "manual", "host": "backend.example.com", "port": 8443}
}
  • 可以修改 route_id、listen_port、transport、target（可以只改其中一部分），以及关闭 native_outbound。至少要带一个字段。
  • 修改成功后返回新的转发和新的 ETag。
  • 换线路、换传输方式、改目标类型、或把 listen_port 改成 null 重新分配时，平台会重新安排节点。如果线路暂时不可用，返回 409 route_unavailable，原来的转发保持不变。
  • 从手动目标改成指向服务（或反过来）时，要在同一次请求里带齐 source 和 service_id（或 host）。
  • 每次修改都会重建这条转发的连接，请不要高频调用。

删除转发

DELETE /api/v1/user/forwards/123
Authorization: Bearer <你的 API 令牌>
If-Match: "forward-123-r4"
  • 删除成功返回 204，没有响应体。ETag 不匹配时不会删除任何东西。
  • 每个服务最多保留 512 条已删除记录，超过后无法再创建转发（返回 409 forward_storage_quota_exceeded），需要联系客服清理。请不要反复创建再删除。

Native Outbound（设备侧出站）

Native Outbound 转发由你的设备直接出站，而不是经过平台入口。创建时不需要填 target：

{"route_id": 14, "listen_port": null, "transport": "tcp+udp", "native_outbound": true}
条件不满足时返回
线路支持 Native Outbound，并且 transport 是 tcp+udp422 native_outbound_requires_ultra_tcp_udp
你的套餐开启了 Native Outbound403 native_outbound_not_allowed
线路配置了方向422 native_outbound_direction_missing
同一个服务里，这个方向还没有其他 Native Outbound 转发409 native_direction_conflict

要关闭 Native Outbound，用 PATCH 发送 {"native_outbound": false, "target": {"source": "manual", "host": "…", "port": …}}。要把普通转发改成 Native Outbound，请新建一条，或在控制台里修改。

超时重试与并发

  • 查询类请求可以随意重试。
  • 创建请求超时没收到结果时，用同一个 Idempotency-Key 和完全相同的内容重试，会返回原来那条转发（200），不会重复创建。
  • 同一个 Idempotency-Key 发送不同内容，返回 409 idempotency_conflict；原来那条已被删除，返回 409 idempotency_resource_inactive。
  • 修改或删除收到 412 forward_version_conflict，说明转发已被改过：重新查看详情，确认后用新的 ETag 再操作。
  • 同时发起多个创建请求也不会超出 forward_limit。

错误码

出错时统一返回：

{
  "ok": false,
  "error": {
    "code": "validation_failed",
    "message": "The forward request is invalid.",
    "fields": {"target.port": "out_of_range"}
  }
}

validation_failed 的 fields 是“字段 → 原因”的对象；unknown_fields 的 fields 是多余字段名的列表，例如 ["target.foo"]。

HTTP错误码含义
401user_auth_failed令牌无效或账号已停用
403feature_denied_manage_forwards、feature_denied_delete_forwards套餐不允许这个操作
403native_outbound_not_allowed套餐未开启 Native Outbound
404service_not_found、forward_not_found不存在、不属于你或已删除
409service_inactive服务已停用或已到期
409forward_quota_exceeded生效转发数已达上限
409forward_storage_quota_exceeded已删除记录达到上限
409idempotency_conflict、idempotency_resource_inactive见「超时重试与并发」
409route_unavailable线路当前不可用
409native_direction_conflict该方向已有 Native Outbound 转发
412forward_version_conflictIf-Match 与当前版本不一致
413request_too_large请求体超过 16 KiB
415unsupported_media_type不是 application/json
422validation_failed、unknown_fields字段不合法，或有多余字段
422idempotency_key_invalidIdempotency-Key 格式不对
422forward_route_not_allowed、forward_route_has_no_enabled_combination线路不在你的套餐内，或线路暂未开放
422native_outbound_requires_ultra_tcp_udp、native_outbound_direction_missing线路不支持 Native Outbound
428idempotency_key_required、precondition_required缺少 Idempotency-Key 或 If-Match
500operation_failed平台内部错误，请稍后重试或联系客服

旧版接口

/api/user/… 开头的旧接口仍然可用，但已经停止更新，也没有 ETag 和防重复创建保护。新的集成请只使用本文的 v1 接口。
