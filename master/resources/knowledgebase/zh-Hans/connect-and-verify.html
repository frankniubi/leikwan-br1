你将完成什么

你将根据应用所在设备选择正确的客户端地址，通过转发发出真实请求，并区分面板状态、运行连接和目标应用成功这几类证据。

开始前准备

  • 记下转发的本地端口。
  • 确认客户端有最近同步，转发显示 Running。
  • 确认应用与客户端在同一台设备上，还是位于另一台设备。
  • 准备符合应用协议的测试；仅检查 TCP 端口不能证明 HTTP、SSH、数据库或游戏请求可用。

地址选择取决于应用在哪里运行。同机连接使用回环地址；跨设备只能通过网络可达的 Windows 或 Linux 客户端主机，并可能需要有限的网络放行；Android 的监听默认仅限回环，除非另有受支持的暴露方案。

  1. 应用与客户端同机时，填写 127.0.0.1 和转发的本地端口。
  2. 另一台设备需要访问 Windows 或 Linux 客户端时，填写可访问的 Windows 或 Linux 客户端主机地址和相同端口。
  3. 只在主机防火墙中放行所需端口。
  4. 云主机按需在安全组中放行该端口。
  5. 客户端位于路由器后方时，仅在网络负责人批准后配置 NAT。
  6. 不要把 Android 当作跨设备监听器；没有单独暴露方案时，它仅监听回环地址。
  7. 使用实际应用协议发出请求。
  8. 检查应用响应；可查看目标端时，再核对目标日志。

如何确认成功

应用通过所选客户端地址和本地端口获得预期响应，目标日志也能对应到该请求时，连接才真正通过。Connected、Running 和开放的本地端口都是中间状态，不能单独证明目标应用已处理请求。

如果没有成功

先停止开放大范围端口；公网 IP 并非默认连接入口。重新核对同机或跨设备地址、本地端口和目标服务；先从目标主机测试后端，再提交已去除秘密的错误、时间、客户端平台和转发名称。
