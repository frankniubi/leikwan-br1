你将完成什么

你将仅在线路方案明确要求时创建并验证 Sidecar。Sidecar 是目标侧的中间传输组件，不是目标应用，也不是 Bond 转发的通用必备组件。

开始前准备

  • 确认所选 Bond 套餐已发布的线路约定明确要求 Sidecar。
  • 准备一台可以访问后端服务的目标侧主机。
  • 向管理员确认 Sidecar Host 和 Bond 传输端口。
  • 准备 Sidecar 主机上相当于 root 的权限。
  • 面板生成的安装命令和所有凭据都必须保密。

Sidecar 位于托管路径与目标服务之间。它既要在线，也要能访问后端监听；但最终仍需通过真实应用请求单独验证目标服务。

  1. 在 Advanced 下打开 Target Endpoints。
  2. 选择 Create 标签页。
  3. 在 Create Transport Endpoint 中填写容易识别的 Name。
  4. 填写管理员确认的 Sidecar Host。
  5. 在 Transport Listen Port 填写获准的 Bond 传输端口。
  6. 选择 Save Transport Endpoint。
  7. 在卡片中打开 Install Command 并复制，但不要展示命令内容。
  8. 以相当于 root 的权限在 Sidecar 主机上运行命令。
  9. 回到面板，等待 Last Heartbeat、Agent Version 和 Last Status 更新。
  10. 从 Sidecar 主机直接测试配置目标地址和端口上的后端监听服务。
  11. 根据已发布线路约定创建或刷新 Bond 转发，并验证客户端连接。

如何确认成功

Sidecar 应报告最近心跳和预期代理状态，Bond 转发也应能把真实应用请求送到目标。仅有心跳不能证明后端健康；必须另行测试后端监听服务，并尽可能在目标日志中确认请求。

如果没有成功

先停止随意更改端口、地址或线路设置。没有心跳时检查 Sidecar 服务与出站网络；心跳正常但应用失败时，从 Sidecar 主机测试后端。联系支持时不要提交令牌、密码、命令、密钥、会话或线路材料。
