The forward is saved and the app is online. The last step is telling the game where to connect.

What you will accomplish

The game pointed at the client, plus proof that traffic is really flowing.

Before you begin

  • A saved forward and the local port the panel assigned to it.
  • The app installed and signed in on the device that runs the client.
  • A few minutes to test while the game is open.

Steps

  1. Ask one question: does the game run on the same device as the client? The answer decides the address you type.
  2. Same device: use 127.0.0.1 and the assigned local port. This is the common case, and it stays loopback-only, so nothing else on your network can reach it.
  3. Another device: use a reachable Windows or Linux client-host address with the same port, and allow that port through the firewall, security group, or NAT between the two.
  4. Start the game and connect. Then look at the forward row while you play.

Same device keeps the port on loopback only. Another device needs one allowed path through the network in between.

How to know it worked

Two checks. The app shows the line as running, and the forward row shows incoming traffic while you play. On Android the client runs on the phone itself, so the game there always uses 127.0.0.1 too.

If it did not work

Stop and check the address first. In order of likelihood: the port does not match the assigned local port; a firewall or NAT rule blocks the another-device case; the target service is down - test the target service from its own host and read the target logs. Test the actual application protocol, not a ping.
