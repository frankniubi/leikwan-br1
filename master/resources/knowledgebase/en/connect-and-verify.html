What you will accomplish

You will choose the address that matches where your application runs, send a request through the Forward, and separate a panel status from proof that the target application received traffic.

Before you begin

  • Record the Forward's local port.
  • Confirm that the Client has a recent sync and the Forward shows Running.
  • Know whether the application runs on the Client device or on another device.
  • Use a protocol-aware test. A TCP port check alone does not prove an HTTP, SSH, database, or game request works correctly.

The deciding fact is where the application runs. Same-device traffic uses loopback. Cross-device traffic is possible only through a reachable Windows or Linux Client host and may need network access rules; Android remains loopback-only unless it is separately exposed by another supported setup.

  1. If the application is on the Client device, enter 127.0.0.1 and the Forward's local port.
  2. If another device uses a Windows or Linux Client, enter a reachable Windows or Linux client-host address and the same local port.
  3. For cross-device access, allow that port in the host firewall.
  4. If applicable, allow it in the cloud security group.
  5. If the Client is behind a router, configure NAT only when your network owner approves it.
  6. Do not present Android as a cross-device listener. Its listener stays loopback-only unless separately exposed through an approved design.
  7. Send a request with the actual application protocol.
  8. Check the response and, when available, confirm receipt in the target logs.

How to know it worked

Your application receives the expected response through the Client address and local port. The strongest confirmation is a matching request in the target logs. Connected, Running, and an open local port are useful checkpoints, but none alone proves the destination application handled the request.

If it did not work

Stop before opening broad firewall ranges or assuming a public IP always works. Recheck same-device versus cross-device addressing, confirm the exact local port, and test the destination service from its own host. Then use diagnostics or ask support with the error, time, Client platform, and Forward name, but no secrets.
