A forward carries packets from your local listen port to a remote target server, while a cloud node is a saved server configuration that your client can use directly. Understanding how they pair is key to setting up forwards correctly.

Two Concepts

A forward is a routing rule: from a local listen port on your device, deliver packets to a specific port on a remote target server on the internet.

A cloud node is a saved server configuration that a client can use directly. Think of a node as a snapshot of "target server details": it records the server address, port, protocol, password, and other parameters needed to connect.

The Core Rule

A forward is paired with exactly one node: the local port and node are one-to-one. Multiple forwards should not share the same node, except when they fully meet the reuse conditions below.

When You Can Reuse the Same Node

Another forward can reuse a node only if all three of these elements match the node exactly:

  1. Target server port — for example, both are 30522.
  2. Protocol — for example, both are Shadowsocks 2022.
  3. Password — the authentication key to log in to that server.

If even one item differs, you must create a new forward and a new node. Reusing a node with mismatched settings always fails.

Automatic Pairing: How the Panel Matches Them

The panel automatically finds a matching node based on the forward's target (server and port). If a node's server and port match the forward's target, they pair automatically. This is convenient, but automatic pairing does not verify protocol or password match. Before reusing a node, you must verify yourself: all three elements really are identical.
