What you will accomplish

You will go from an active package to one verified Forward without changing advanced settings. The goal is not merely to save a configuration. The goal is to send a real request through the assigned local port and receive the expected response.

Before you begin

  • Confirm that your package or service is marked Active.
  • Know the destination host, destination port, and whether the application uses TCP, UDP, or both.
  • Have a supported Windows, Android, or Linux device ready for the Client.
  • Never share passwords, tokens, copied install commands, private keys, or route material.

The shortest safe path has one decision: if an application request succeeds through the local listener, setup is complete; if it fails, keep the saved Forward and troubleshoot the visible symptom.

  1. Open the active service in the tenant panel.
  2. Select Create Forward.
  3. Choose the offered route package and enter the destination.
  4. Save the Forward and record its assigned local port.
  5. Install the Client and sign in.
  6. Wait for a recent client sync.
  7. Point your application at the local listener.
  8. Test with the actual application protocol, such as an HTTP request, SSH connection, or game connection.

How to know it worked

The panel shows an active endpoint after provisioning, the Client shows a recent sync, and the Forward reaches Connected or Running. Those signals are different from final proof. Final proof is that the application request succeeds and returns the expected result. If you control the target, its logs should also show the request arriving.

If it did not work

Stop before changing route details at random. Keep the first Forward, note the exact error and time, then open the troubleshooting guide. A saved configuration, completed provisioning, recent sync, running process, and successful application request are separate checkpoints.
