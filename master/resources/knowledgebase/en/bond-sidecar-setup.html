What you will accomplish

You will create and verify a Sidecar only when a Bond package's published route contract requires one. A Sidecar is intermediate target-side transport. It is not the target application.

Before you begin

  • Confirm that the selected Bond package explicitly requires a Sidecar.
  • Have a target-side machine that can reach the backend service.
  • Know the approved Sidecar Host and Bond transport port.
  • Have root-equivalent permission on the Sidecar machine.
  • Keep the panel-provided install command and all credentials secret.

The Sidecar sits between the managed path and the target service. It must be online and able to reach the backend, but users still verify the target application separately.

  1. Open Target Endpoints under Advanced.
  2. Select the Create tab.
  3. In Create Transport Endpoint, enter a recognizable Name.
  4. Enter the approved Sidecar Host.
  5. Enter the approved Bond transport port in Transport Listen Port.
  6. Select Save Transport Endpoint.
  7. On its card, open Install Command and copy it without exposing its contents.
  8. Run it on the Sidecar machine with root-equivalent permission.
  9. Return to the panel and wait for Last Heartbeat, Agent Version, and Last Status to update.
  10. From the Sidecar machine, test the backend listener at the configured target host and port.
  11. Create or refresh the Bond Forward as directed by the published route contract.

How to know it worked

The Sidecar reports a recent Last Heartbeat, the expected agent status, and the Bond Forward can carry a real application request to the target. A heartbeat alone does not prove backend health. Separately test the backend listener and, if possible, confirm the request in target logs.

If it did not work

Stop before changing ports, addresses, or route settings at random. If heartbeat is missing, check the Sidecar service and outbound access. If heartbeat is current but the application fails, test the backend from the Sidecar host. Share diagnostics with support, but never share the generated install command, tokens, passwords, route keys, private keys, or internal line or session material.
