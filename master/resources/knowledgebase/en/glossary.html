What you will accomplish

You will understand the product and network terms used throughout the beginner guides, without needing to learn the internal implementation.

Before you begin

  • Keep the relevant guide open so you can match each term to a visible field or status.
  • Remember that similar-looking status words can prove different checkpoints.
  • Do not copy secret values while asking what a term means.

Steps

  1. Active package: A purchased package or service that currently allows you to create and use a Forward.
  2. Forward: A saved instruction that sends traffic from a Client listener to a target host and port through an offered route.
  3. Forward Route: The route package offered in the first Forward form. Choose the published option that matches your service.
  4. Target Host: The hostname or IP address of the destination service.
  5. Target Port: The destination service's port.
  6. Local Listen Port: The port on the Client side that your application connects to.
  7. Client: The Windows, Android, or Linux software that receives your Forward configuration and creates the local listener.
  8. Recent sync: Evidence that the Client recently pulled configuration from the panel. It does not prove the target application responded.
  9. Running: A Client status showing that the Forward process is active. It is not final application proof.
  10. Single: The simplest supported connection mode, using one route path for a request.
  11. Race: A redundancy or path-selection mode. It is not bandwidth aggregation, and behavior depends on platform and transport.
  12. Bond: An advanced mode used only when the package and platform explicitly support its published requirements. It does not guarantee doubled speed or use of every path.
  13. Sidecar: Optional intermediate target-side transport required by some Bond routes. It is not the target application.
  14. Application verification: A real request made with the intended protocol that receives the expected response, ideally confirmed in target logs.

How to know it worked

You can identify which value belongs in each visible field, distinguish delivery and process states from application success, and choose the correct guide without guessing.

If it did not work

Stop before guessing a value or sharing a secret. Use the plain cross-references below, then ask your administrator or support to explain the visible label in context.

Related guides
